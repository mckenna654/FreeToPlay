# Safer logins that survive restarts

This update fixes two weaknesses in how FreeToPlay remembers who is signed in. There is nothing you need to change.

## What's fixed

- **Login cookies can no longer be forged on installs without a secret.** If `SESSION_SECRET` was never set, the app used to fall back to a value published in its source code. It now creates a private random secret on first start and saves it as `session-secret` in `/app/data`. Example values such as `super-secret-session-key` are ignored for the same reason.
- **Restarts and image updates no longer sign everyone out.** Logins are now saved in `sessions.db` in `/app/data`, and the memory leak warning at startup is gone.

## Upgrading

- **`SESSION_SECRET` set to your own value:** it keeps working as before. Everyone signs in once more after this update, as they do after any restart today.
- **`SESSION_SECRET` empty or an example value:** the app switches to a generated secret on its own. Everyone signs in once more. If you were on an example value, you can clear it from your container settings; the startup warning tells you it is being ignored.
- **Make sure `/app/data` is mapped to a folder on your server.** The Unraid path in the README already does this. Without it, the secret and logins are lost whenever the container is recreated, along with your database.

Include `session-secret` in any backup of the data folder, and keep it private. Deleting `session-secret` or `sessions.db` while the container is stopped is safe: it only signs everyone out.
